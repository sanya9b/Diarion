# 06 — Кореляційний рушій інсайтів

- **Priority:** P1 · **Effort:** L · **Status:** Done · **Depends on:** 05 · **Blocks:** —

## Продукт

**Проблема/можливість.** Diarion обіцяє «smart diary», але «розумність» зараз — це порожнє поле `AiSummary` +
прості агрегатні діаграми. Водночас застосунок уже збирає рідкісно багатий мультимодульний набір (настрій,
сон, звички, шкідливі звички, їжа, цикл, фінанси) — ідеальне пальне для інсайтів.

**Конкуренти.** Bearable («Impacts»), Exist (кореляції зі strength+confidence), Daylio (activity–mood),
Moodfit — **монетизують** саме кореляції; просте логування безкоштовне й є в усіх. Frontier 2025: lagged-
кореляції (Bearable: same-day / +1 / +7). Відома вада лідерів — показ кореляцій без коефіцієнтів/довіри =
оманливо; цього треба уникнути.

**Цінність.** Головний диференціатор: **приватний-за-архітектурою + мультимодульні кореляції на пристрої** —
комбінація, якої немає в жодного лідера повністю. Природний кандидат у платний «Diarion Pro».

**User story.** *Як користувач, я хочу бачити, що впливає на мій настрій (сон, звички, цикл, витрати), з
чесним показником сили та надійності зв'язку, щоб робити кращі рішення.*

## Інженерія

### Проблема / докази
- Дані є: `DiaryEntry` (сон, `SleepQuality`, `HabitsList`, `Emotion`/`MoodScale`, їжа), `HarmfulHabitTracker`,
  `FinanceTransaction`, цикл (`MenstrualCycleService`). Немає сервісу, що їх корелює.
- `Diarion.Core/Services/StatisticsService.cs` рахує лише прості агрегати; `IStatisticsService` не має кореляцій.
- Передумова — заповнений `Emotion` (див. spec 05) і valence-маппінг.

### Вимоги (Requirements)
- **R1.** `Emotion` → числовий **valence-скор** (напр. −2..+2) у Models-шарі (атрибут/маппінг), опційно
  додати `arousal` для 2D-моделі (How We Feel-стиль) у майбутньому.
- **R2.** Новий `Diarion.Core/Services/CorrelationService` (+ `ICorrelationService`): обчислює
  Pearson/Spearman між денним valence і денними агрегатами факторів: тривалість/якість сну, к-сть виконаних
  звичок, шкідливі-звички-події, прапорці їжі, фаза циклу, сума витрат.
- **R3.** Розширити `IStatisticsService` (або окремо) методом
  `GetMoodCorrelationsAsync(int days, int lagDays=0)` → ранжований список
  `{ factor, coefficient, strength, confidence, sampleSize, lagDays }`.
- **R4.** **Чесність:** кожна кореляція за мінімальної вибірки (напр. ≥14 парних днів); confidence з
  sampleSize + p-value; UI — 1..5 крапок + локалізований дисклеймер «зв'язок, а не доведена причина».
  Низькодовірчі — приховані за замовчуванням.
- **R5.** **Lagged-кореляції:** параметр `lagDays` (0..7) зсуває серію фактора відносно настрою; UI —
  сегментований контрол (Сьогодні / +1 / +3 / +7). Особливо для сон→настрій-завтра, шкідливе→настрій-завтра.
- **R6.** Рендер «Що впливає на ваш настрій» — ранжований список у `StatisticsPage` (переюзати наявний UI).
- **R7.** Усе — **на пристрої**, без мережі; важкі обчислення поза UI-потоком (`Task.Run`), кеш результатів.

### Критерії приймання (Acceptance)
- **AC1.** За синтетичних даних із відомою залежністю (сон↑→настрій↑) сервіс повертає позитивний коефіцієнт
  правильної величини; за шумових даних — низьку довіру/приховано.
- **AC2.** Фактори з <14 парних днів не показуються як впевнені (мають низьку confidence/приховані).
- **AC3.** `lagDays=1` виявляє залежність «вчорашній сон → сьогоднішній настрій» на відповідному датасеті.
- **AC4.** Обчислення не блокують UI; повторний виклик використовує кеш.
- **AC5.** `CorrelationService` покритий unit-тестами на еталонних наборах (включно з edge: нульова дисперсія,
  пропуски днів).

### Тест-план
- Unit: Pearson/Spearman проти еталонних значень; confidence vs sampleSize; lag-зсув.
- Unit: edge-кейси (нульова дисперсія, всі однакові, розриви в датах).
- Manual: реальні дані за ≥30 днів → осмислений ранжований список.

### Ризики / застереження
- **Ризик оманливості** — головний; суворо гейтити за вибіркою/довірою і завжди показувати дисклеймер.
- Множинні порівняння (багато факторів) → ризик хибних кореляцій; розглянути корекцію/поріг.
- Це фундамент для майбутнього opt-in AI-формулювання інсайтів (P2), але сам рушій — детермінований і локальний.
