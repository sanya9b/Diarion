# 08 — Доступність та адаптивний UI

- **Priority:** P1 · **Effort:** M/L · **Status:** Done · **Depends on:** — · **Blocks:** —

## Продукт

**Проблема.** Застосунок фактично непридатний для screen-reader користувачів (нуль `SemanticProperties`,
більшість «кнопок» — Label/Border з tap-gesture), не підтримує масштабування системного шрифту (Dynamic
Type), не адаптується під планшети/ландшафт, а вторинний текст провалює контраст WCAG AA. Плюс є хардкод-рядки,
що ламають двомовність.

**Конкуренти.** Провідні застосунки (Apple Journal, Day One) підтримують VoiceOver/TalkBack і Dynamic Type
«з коробки» — це вимога App Store/Play і етичний мінімум для щоденника, яким користуються люди з різними
можливостями.

**Цінність.** Розширює аудиторію (низький зір, похилий вік), знижує ризик відхилення в сторах, підвищує
загальну якість/полиск. Значна частина — дешеві семантичні атрибути.

**User story.** *Як користувач зі слабким зором / screen-reader, я хочу чути назви й ролі елементів,
збільшувати шрифт без обрізання тексту і зручно користуватися застосунком на планшеті.*

## Інженерія

### Проблема / докази
- Нуль `SemanticProperties`/`AutomationProperties` у всіх `Views/*.xaml` і `Controls/*.xaml`; інтерактив —
  переважно `TapGestureRecognizer` на Label/Border/Grid (не `Button`), тож не оголошується й не фокусується.
- Фіксовані розміри шрифтів (багато 9–13px) + фіксовані піксельні висоти → обрізання при збільшенні шрифту.
- Немає `OnIdiom`/`AdaptiveTrigger` — все одноколонково з фіксованими 24px gutters.
- Ocean `#929FA7` на Snow `#FFFFFF` ≈ 2.6:1 — провал AA (треба ≥4.5:1); це дефолт для дрібного вторинного тексту.
- Хардкод-рядки (напр. екран блокування) не локалізовані.
- Стан подекуди сигналізується лише кольором (обрана вкладка, дні звичок, пріоритети) — проблема для дальтоніків.

### Вимоги (Requirements)
- **R1.** Додати `SemanticProperties.Description` (і `.Hint` де треба) на всі інтерактивні/іконкові елементи;
  для tap-Label/Border задати `SemanticProperties` або перевести на `Button`/додати `AutomationProperties`.
  Пріоритет: `NotesPage`, `HabitTrackerPage`, `QuickMenuView`, `StatisticsPage`, `MainPage`, close/create/delete.
- **R2.** Підтримати Dynamic Type: замінити фіксовані `FontSize` на масштабовані значення/`NamedSize`, прибрати
  фіксовані висоти там, де вони обрізають текст; перевірити при 200% шрифті.
- **R3.** Адаптив: `OnIdiom`/`AdaptiveTrigger` + `MaxWidth`-контейнер у `Styles.xaml`, дво-колонкові розкладки
  на планшеті/ландшафті замість розтягнутого одного стовпця.
- **R4.** Підняти контраст вторинного тексту до AA (≥4.5:1) — скоригувати токен `Theme_Ocean_*` у Light/Dark.
- **R5.** Додати не-колірні сигнали стану (іконка/форма/текст) поряд із кольором.
- **R6.** Виправити хардкод-рядки → у `.resx` (UK/EN), закрити ключі, що є лише в `uk.resx`, — додати нейтральні.
- **R7.** Виправити дрібні dark-theme токени (кольори корінця книги, тінь картки однакові в Light/Dark).

### Критерії приймання (Acceptance)
- **AC1.** TalkBack/VoiceOver оголошує назву й роль для всіх основних дій на пріоритетних екранах.
- **AC2.** При системному шрифті 200% ключові екрани не обрізають текст і лишаються придатними.
- **AC3.** На планшеті/ландшафті контент використовує ширину розумно (не розтягнутий один стовпець).
- **AC4.** Контраст вторинного тексту ≥4.5:1 (перевірено контраст-чекером) у Light і Dark.
- **AC5.** Немає хардкод user-facing рядків; перемикання UK/EN не лишає англійських «хвостів».
