# 09 — Портативний експорт даних

- **Priority:** P1 · **Effort:** M · **Status:** Proposed · **Depends on:** — · **Blocks:** —

## Продукт

**Проблема.** Єдиний «експорт» — непрозорий бінарний `.db`, який неможливо прочитати без ідентичної збірки
Diarion. Користувач не може дістати власні дані у переносному вигляді (переглянути, мігрувати, роздрукувати).

**Конкуренти.** Journey (JSON/ePub), Day One (PDF/експорт), Health Export Kit (Markdown/JSON/CSV/Obsidian).
Daylio експортує PDF/CSV (у преміумі). «Ваші дані, портативні та ваші» — прямий контраст до cloud lock-in.

**Цінність.** Підсилює privacy/ownership-наратив; знімає страх lock-in; PDF/CSV mood+кореляцій — цінний для
терапії/самоаналізу; природний кандидат у платний Pro (окрім базового JSON, який має лишатися безкоштовним).

**User story.** *Як користувач, я хочу експортувати свій щоденник/фінанси/звички у відкритому форматі
(Markdown/JSON/CSV/PDF), щоб володіти власними даними й ділитися ними за бажанням.*

## Інженерія

### Проблема / докази
- `Diarion.Core/Services/BackupService.cs` — лише бінарний бекап БД; немає людиночитаного експорту.
- Дані структуровані per-collection (`DiaryEntry`, `FinanceTransaction`, `HabitDefinition`, `TodoItem` тощо) —
  придатні до серіалізації в JSON/CSV/Markdown.

### Вимоги (Requirements)
- **R1.** Новий `Diarion.Core/Services/ExportService` (+ `IExportService`), окремо від бекапу.
- **R2.** Формати:
  - **JSON** — повний структурований експорт усіх колекцій (машиночитаний, для міграції/резерву).
  - **Markdown** — per-entry щоденник (Obsidian-friendly: дата, настрій, рефлексія, звички).
  - **CSV** — фінанси, звички, настрій (для таблиць/аналізу).
  - **PDF** — вибраний діапазон дат (щоденник + графік настрою + топ-кореляції зі spec 06) — «book export».
- **R3.** Вибір діапазону дат і набору модулів для експорту.
- **R4.** Запис у приватну теку → `Share`/збереження у Files/користувацьку локацію; прибирати temp після share.
- **R5.** Культурно-коректне форматування дат/чисел/валюти (переюзати .resx-локаль).
- **R6.** Платформні залежності (`Share`, файлова система, PDF-рендер) — за абстракцією (координація зі spec 10),
  щоб `ExportService` тестувався.
- **R7.** Приватність: базовий JSON/Markdown/CSV — безкоштовно; ніколи не гейтити експорт за paywall повністю
  (може бути Pro лише для PDF/розширеного).

### Критерії приймання (Acceptance)
- **AC1.** JSON-експорт містить усі записи всіх обраних колекцій і валідно парситься назад.
- **AC2.** Markdown-експорт дає по файлу/секції на день у читабельному вигляді.
- **AC3.** CSV відкривається у Excel/Sheets із коректними колонками й культурним форматуванням.
- **AC4.** PDF за діапазон містить записи + графік настрою + топ-кореляції.
- **AC5.** Після share temp-файли видалено; нічого зайвого не лишається в cache.

### Зачеплені файли
- Новий: `Diarion.Core/Services/ExportService.cs`, `IExportService.cs`
- (Abstraction) `IShareService`/`IFileService` — Core-інтерфейси + app-реалізації (spec 10)
- `Diarion.Core/ViewModels/ProfileViewModel.cs`, `Views/ProfilePage.xaml` (UI експорту)
- `Extensions/ServiceCollectionExtensions.cs`
- Тести: новий `Diarion.Tests/ExportServiceTests.cs`

### Тест-план
- Unit: JSON round-trip (export→parse); CSV-колонки; Markdown-структура (мок file/share).
- Manual/E2E: PDF-рендер на пристрої; share у Files/Drive; перевірка видалення temp.

### Ризики / застереження
- PDF-рендер у MAUI може вимагати платформного коду/бібліотеки — оцінити; MVP може відкласти PDF на другу ітерацію.
- Великі експорти — виконувати поза UI-потоком із прогресом.
