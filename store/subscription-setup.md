# Підписка в App Store Connect — що зробити і в якому порядку

Спека 15, R6. Код готовий і чекає лише на продукти в магазині: поки в App Store Connect немає
підписок і не діє Paid Applications Agreement, `Product.products(for:)` повертає порожній список
навіть у пісочниці, і пейвол показує «App Store зараз недоступний». Це не помилка коду.

Кроки йдуть по черзі: кожен наступний без попереднього не запрацює.

---

## 1. Договір, банк, податки (Business → Agreements)

1. **Paid Applications Agreement** — прийняти. Приймає лише Account Holder.
2. **Банк** — рахунок для виплат у USD (у ФОП — валютний рахунок).
3. **Податки** — форма W-8BEN для фізичної особи-нерезидента США; податкові форми інших країн за
   запитом ASC.
4. Статус договору має стати **Active**. До того продуктів не видно ніде, навіть у пісочниці.
5. **Small Business Program** — заявка на developer.apple.com/app-store/small-business-program
   після активного договору. Комісія 15% замість 30% діє з дати схвалення, не заднім числом, тож
   подавати її варто до першого продажу.

## 2. Група підписок (Diarion → Monetization → Subscriptions)

**Subscription Group**, Reference Name: `Diarion Base`. Код групу за ідентифікатором не шукає, тож
назва довільна; ця збігається з тарифом.

Локалізація групи (Subscription Group Display Name), обидві мови: `Diarion Base`;
App Name Display Options — Use App Name.

## 3. Два продукти в групі

Product ID — **точно так**, як у коді (`Diarion.Core/Services/Store/StoreCatalog.cs`); змінити ID
після створення неможливо.

| Поле | Місячна | Річна |
|---|---|---|
| Reference Name | `Diarion Base Monthly` | `Diarion Base Yearly` |
| Product ID | `diarion.base.monthly` | `diarion.base.yearly` |
| Subscription Duration | 1 Month | 1 Year |
| Level (ранг у групі) | 1 | 1 |
| Family Sharing | **вимкнено** | **вимкнено** |

Обидві на одному рівні: перехід між місяцем і роком — це зміна плану того самого тарифу. Коли
з'явиться Plus, його ставлять вище (Level 1), а Base опускається на 2 — тоді Apple сам рахує
доплату при переході. Family Sharing вимкнений навмисно (рішення 7): увімкнути потім можна,
вимкнути — ні.

**Локалізація продуктів** (Display Name ≤ 30 знаків, Description ≤ 45):

| | Українська | English |
|---|---|---|
| Місячна — назва | `Diarion Base — місяць` | `Diarion Base — Monthly` |
| Місячна — опис | `Повний доступ до запису на місяць` | `Full writing access for one month` |
| Річна — назва | `Diarion Base — рік` | `Diarion Base — Yearly` |
| Річна — опис | `Повний доступ до запису на рік` | `Full writing access for one year` |

## 4. Ціни

Базова країна — США, решту вітрин Apple генерує сам. Українська вітрина App Store показує ціни в
доларах — це обмеження Apple, у текстах магазину для UA це вже сказано.

- Місячна: **$1.99** або **$2.49** — вибір за вами.
- Річна: **$11.99**.

Знижку на картці річної застосунок рахує сам із двох цін (у ресурсах чисел немає), тож вона
залежить від вибору: $1.99 × 12 = $23.88 → **−50%**; $2.49 × 12 = $29.88 → **−60%**. «−53%» зі
спеки — це гривневий розрахунок 89/499, на долари він не переноситься.

## 5. Безкоштовні 14 днів (Introductory Offer)

На **кожному** з двох продуктів: Subscription Prices → Introductory Offers → Create:
- Countries: усі;
- Start date: сьогодні, End date: без кінця;
- Type: **Free**, Duration: **2 Weeks**.

Право на нього визначає Apple (один раз на групу для Apple ID); застосунок лише показує текст
«14 днів безкоштовно» там, де StoreKit каже, що людина має право.

## 6. Інформація для рев'ю на кожному продукті

- **Screenshot** — знімок пейволу з телефона (з TestFlight-збірки, коли продукти з'являться;
  до того — будь-який знімок екрана підписки, його можна замінити).
- **Review Notes**: `Unlocks writing. Without it the app is read-only; see the version's Review Notes.`

## 7. Перевірка на телефоні (TestFlight + пісочниця)

1. Users and Access → **Sandbox** → створити тестовий Apple ID (нова пошта, не ваша основна).
2. Залити збірку 3 (`build-ios.yml`, підписаний режим) у TestFlight.
3. На iPhone: Параметри → App Store → Sandbox Account → увійти тестовим акаунтом.
4. Прогін зі спеки (тест-план): свіже встановлення → онбординг → пейвол з цінами й «14 днів» →
   оформити → «Тріал до …» у Налаштуваннях → у пісочниці місяць триває 5 хвилин, тож за пів години
   видно поновлення → скасувати в «Керувати підпискою» → після кінця — банер «Підписка
   закінчилась», режим читання, бекап працює → «Відновити покупки».
5. **Правило користувачів 1.0** у пісочниці від Apple не спрацює (там `originalAppVersion` завжди
   «1.0»), але локальне перевіряється так: на телефоні з Diarion 1.0 з App Store, де онбординг уже
   пройдено, поставити збірку 3 з TestFlight поверх — на головній має з'явитись картка «Дякуємо,
   що ви з нами з першої версії», у Налаштуваннях — текст обіцянки, пейволу — жодного разу.

## 8. Сайт — до подачі, не раніше

`site/terms.html`, `site/en/terms.html` і оновлені `privacy.html` / `en/privacy.html` описують
підписку, якої до релізу ще немає. Опублікувати їх (Cloudflare Pages — `site/README.md`) після того,
як продукти створені, і **до** подачі: рев'юер відкриває посилання з пейволу. Перевірити, що
`https://diarion.org/terms` і `https://diarion.org/en/terms` відкриваються.

## 9. Подача версії 1.1

1. App Store → **+ Version** → `1.1` (у збірці `ApplicationDisplayVersion` уже 1.1, номер збірки 3).
2. Build — збірка 3.
3. Розділ **In-App Purchases and Subscriptions** на сторінці версії → додати обидві підписки.
   Перші підписки застосунку подаються лише разом із версією — окремо їх не відправити.
4. Опис і «Що нового» — `app-store-listing.md`, розділ 7.
5. Notes для рев'ю — `app-review-notes.md`, розділ 10, і перезаписане відео.
6. App Privacy — лишити «Data Not Collected», звіривши з переліком Apple.
7. Submit for Review.

- Записати результат у `submission-runbook.md`.
